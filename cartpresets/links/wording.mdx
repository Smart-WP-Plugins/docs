You can edit every sentence and label a customer reads, under **Settings → Messages and labels**. There are twenty-one, in four groups: **Error messages**, **Warning messages**, **Cart messages** and **Labels**. Each group shows how many messages it has and how many you've customised. Its **Edit wording** button opens the fields.

The screen shows twenty-two fields for them: `limit_customer` changes with the number, so you edit it as a singular and plural pair.

To find one message, type in the search box above the groups. It matches the wording and the row name, which says when the message shows, and it opens every group so the matches are in view.

A rewritten field gets a **Customised** badge, the shipped wording under it (**Default: “…”**), and a **Reset to default** button. Leave one blank and the shipped wording is used. You only ever store what you changed, so an improved default reaches you automatically.

The tables below list each message by the row name the screen shows.

## Error messages

Ten messages for a link that couldn't be followed, one for each of the ten ways a link is refused. See [Where customers land](/cartpresets/links/destinations#unavailable-links) for where the customer goes next.

| ID | Row | Shipped wording |
| --- | --- | --- |
| `not_found` | The link matches no preset (mistyped, deleted, or renamed more than 30 days ago) | That link is not valid. It may have been changed or removed. |
| `scheduled` | Status is scheduled<Pro /> | This preset is not available yet. |
| `unavailable` | Expired, inactive, or sold out | This preset is no longer available. |
| `not_signed_in` | For signed-in customers only<Pro /> | Please sign in to use this preset. |
| `role_not_allowed` | The customer lacks an allowed role<Pro /> | This preset is not available on your account. |
| `limit_total` | Total cap hit<Pro /> | This preset has reached its purchase limit and is no longer available. |
| `limit_customer` | Per-customer cap hit, when the count is one<Pro /> | This preset is limited to %d purchase per customer. |
| `limit_customer` (plural) | Per-customer cap hit, when it is more than one<Pro /> | This preset is limited to %d purchases per customer. |
| `no_items` | The preset has no items | This preset is not available right now. |
| `item_blocked` | An item failed and the preset adds nothing | This preset is unavailable because one of its items cannot be purchased right now. |
| `nothing_added` | Every add failed at cart time | Nothing in this preset could be added to your cart. |

`item_blocked` only shows when **Settings → Cart behaviour → Unavailable items** is set to **Refuse the preset**.

<Warning>
  Write `not_found` for a stranger. Anyone can guess a URL, and the shipped wording deliberately doesn't say whether the preset ever existed. You can't switch it off either, because an empty override falls back to the default, so it has to be safe in front of anyone.
</Warning>

<Note>
  `not_signed_in` and `role_not_allowed` are store-wide, not per preset. You write them once here and every link uses them, so a wholesale link and a staff link say the same thing.
</Note>

## Warning messages

Four messages for a link that worked with a caveat. Nothing here is a refusal: something reached the cart, so the customer keeps it and **Redirect after adding** decides where they land.

| ID | Row | Shipped wording |
| --- | --- | --- |
| `already_in_cart` | Follows the link again holding the last slot | “%s” is already in your cart. |
| `item_out_of_stock` | Partial add, out of stock | One item in this preset is out of stock. |
| `item_qty_capped` | Partial add, sold individually | One item in this preset is limited to one per order, so the quantity was adjusted. |
| `item_unavailable` | Partial add, everything else | One item in this preset is currently unavailable. |

## Cart messages

Four messages about editing a preset that's already in the cart.

| ID | Row | Shipped wording |
| --- | --- | --- |
| `cascade_removed` | A preset was removed because one of its items changed | That preset has been removed from your cart because one of its items was changed. |
| `quantity_locked` | Quantity is fixed | That item's quantity is fixed by the preset it belongs to. |
| `quantity_min` | Below the minimum | This preset item has a minimum quantity of %d. |
| `quantity_max` | Above the maximum | This preset item has a maximum quantity of %d at the preset price. |

## Labels

Three labels rather than notices, shown on the cart line, the order, and in emails.

| ID | Row | Shipped wording |
| --- | --- | --- |
| `cart_line` | On the cart line, ahead of the preset name | Part of preset |
| `order_line` | On the order and in emails | Part of preset: %s |
| `cart_details` | The second cart row on a custom item<Pro /> (it heads the item's description) | Details |

<Tip>
  `cart_line` is the one most stores change. "Part of preset" is accurate but a little technical. "Bundle", "Included in your kit" or your campaign's own name often reads better to a customer.
</Tip>

## Placeholders

Five messages contain a placeholder that carries a value:

| ID | Placeholder | Becomes |
| --- | --- | --- |
| `limit_customer` | `%d` | The per-customer limit |
| `already_in_cart` | `%s` | The preset name |
| `quantity_min` | `%d` | The minimum quantity |
| `quantity_max` | `%d` | The maximum quantity |
| `order_line` | `%s` | The preset name, as it was when the order was placed |

They're checked when you save. Dropping a placeholder leaves a sentence that reads like a typo, such as *"limited to purchases per customer"*. Adding one would break the cart page in front of a customer.

Either is refused. The save stops, the group holding the row at fault opens, and the error shows under that row, so you can't save a message that would fail later.

## The one plural

`limit_customer` is the only message whose grammar changes with the number, so it's stored as a pair: singular and plural. Each one falls back on its own. Rewrite only the plural and you get your sentence for two and the shipped one for one, rather than *"1 purchases"*.

<Note>
  If your store translates into a language with more than two plural forms, you're better off leaving this one at its default. The default keeps proper plural handling in every locale. An override has exactly two forms, whatever the language.
</Note>

## Translating

There are two halves, and they translate differently.

Wording you haven't touched goes through WordPress's normal translation functions, and it's in the `.pot` file like everything else. You don't need to do anything.

Wording you've rewritten is a value in an option, and an option value is data, not a translatable string. CartPresets ships a `wpml-config.xml` that names every key, so a translation plugin can pick it up.

<Warning>
  WPML needs the String Translation add-on as well as WPML core. Checked against WPML 4.9.7. Core parses the config block, but the class that registers and translates those keys ships with the **WPML String Translation** add-on. Without it the config file is read and then ignored. There's no error or notice, so the wording stays untranslated on a store you think is set up.
</Warning>

**Polylang** reads the same file through its own WPML-config compatibility and needs no add-on.

### Why String Translation only lists some of them

It lists only the ones you've rewritten. That's expected.

WPML builds its list from the keys that are named in the config and held in the option, and CartPresets stores only your overrides. A notice still at its shipped wording has nothing to translate there, because gettext translates it instead.

The list grows as you edit, and a store that has reworded nothing sees an empty list.

## For developers

`cartpresets_notice_text` filters one customer-facing sentence before its values are put in. It receives the wording, the notice ID, and whether this is the plural form of a pair. See the [hooks reference](/cartpresets/developers/hooks-reference#cart).
