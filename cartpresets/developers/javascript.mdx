The admin panel is a bundle of its own, and it publishes **no JavaScript API**. One global exists, and it is data rather than code: the payload the panel is handed before its first fetch.

<Warning>
  This exists on the plugin's **admin page only**. Nothing is enqueued on your storefront, so there is no front-end equivalent and there will not be one.
</Warning>

## The boot payload

Everything the panel is handed at load time is on `window.cartPresetsBoot`:

| Key | Holds |
| --- | --- |
| `restUrl` | The REST base for `cartpresets/v1` |
| `homeUrl` | The site's home URL |
| `version` | Plugin version |
| `now` | The store's current time, on the store's clock rather than the browser's |
| `currency` | Symbol, position, decimals, separators |
| `statuses` | The derived status ladder |
| `filterFields` | The listing's filter grammar, from the allow-list the REST route validates against |
| `settings` | Resolved store settings |
| `isPro` | Whether Pro is running |
| `upgradeUrl` | Where the upgrade call to action points |
| `notices` | The wording catalogue, as `groups` and `items` |
| `licence`<Pro /> | `status`, `expires` and `dismissed`, added by Pro through `cartpresets_admin_boot` |

`now` is there for a reason worth knowing if you read it: a preset's status is derived live, and `new Date()` answers in the visitor's timezone. A merchant abroad, or anyone near midnight, would otherwise see a status the server disagrees with.

## Adding your own keys

Add them from PHP through [`cartpresets_admin_boot`](/cartpresets/developers/hooks-reference#the-admin-panel), and read them here without a second request.

```php
add_filter( 'cartpresets_admin_boot', function ( $data ) {
	$data['myPlugin'] = array( 'enabled' => true );

	return $data;
} );
```

```js
const mine = window.cartPresetsBoot.myPlugin;
```

<Warning>
  That filter is **additive only**. Removing or rewriting an existing key breaks the panel, and nothing downstream checks.
</Warning>

## Nothing else is exported

Two things used to be published here, and both are gone.

**A component library**, removed earlier: the panel is transcribed from a design file rather than built on a component system, and its pieces are shaped by the screens they belong to. Publishing them would have promised an API the next design round would break.

**`window.CartPresetsAdmin`**, removed on 23 September 2026. It exposed the pricing, status and formatting helpers the panel uses internally. It was written for a sibling plugin that was never built, neither version of CartPresets read it, and a global nobody calls is still an API that has to keep working. Those helpers are internal again.

If you were reading it, the shapes it exposed are documented elsewhere, and the server is the better source for all of them:

| You were reading | Ask instead |
| --- | --- |
| `pricing.presetTotals()` | The `totals` block on a preset from [`GET /presets`](/cartpresets/developers/rest-api) — the same arithmetic, computed by the PHP the cart itself uses |
| `status.statusOf()` | `derived_status` on the same payload |
| `format.money()`, `format.shortDate()` | WooCommerce's own `wc_price()` and `wc_format_datetime()`, which is where the panel's currency and date settings come from |
