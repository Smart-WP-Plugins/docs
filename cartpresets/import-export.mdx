<Info>
  Import and export are Pro features. On the free version the routes aren't registered at all, so a request 404s like any unknown route. The admin still shows every export and import control, locked with a Pro tag, so you can see what CartPresets for WooCommerce Pro adds.
</Info>

Presets export as JSON and import somewhere else. The obvious use is moving a staging store's work to production without rebuilding it by hand.

<Media>The listing with several presets selected and the export action visible</Media>

## Exporting

**One preset**: **Export as JSON** in the row menu on the list, or **Export JSON** in the editor's menu.

**Several**: tick them in the list, choose **Export JSON** from the bulk actions, and apply it. To export everything a search or filter matches, select all across pages first.

**All of them**: **Settings → Data management → Preset data → Export presets**.

There's no limit on how many presets one file holds.

The file holds the presets, their items, and every setting on both. It doesn't include your store settings, your wording overrides or any order data.

<Tip>
  The export is plain JSON, so it diffs readably. Commit it to a repository and you get a version history of your presets, which the plugin itself doesn't keep.
</Tip>

## Importing

On the destination store, go to **Settings → Data management → Preset data → Import presets**. Choose the .json file, or drop it on the dialog, and click **Import**. One import takes up to 500 presets. Anything beyond that is reported as skipped, not quietly dropped.

### How products are matched

**By SKU first, falling back to product ID.**

SKU first is the important half. Product IDs almost never line up between two stores: the same hoodie is #412 on staging and #1908 on production. A SKU is a name you chose, so it usually survives the move.

| The import finds | Result |
| --- | --- |
| A product with a matching SKU | Matched |
| No SKU match, but the ID exists | Matched by ID |
| Neither | The item keeps the source store's product ID. If no product has that ID here, the item can't be added, and once the preset is active the list marks it **Needs attention** |

<Warning>
  An ID-only match is a guess. If your two stores have unrelated product IDs, an import can quietly attach the wrong product. Check imported presets before you activate them. The next section makes that easy.

  **Variations always travel by ID.** Only the parent product is matched by SKU, so a variation item imported into a different store nearly always needs choosing again.
</Warning>

### Every import arrives inactive

Whatever the status was on export, imported presets land **inactive**.

No link goes live unasked. You get to open each one, check the items matched the products you expected, look at the **Health checks**, and activate when you're ready.

### Slugs

An imported slug that's already taken on the destination store gets a numbered suffix, the same way a manually created one does. The import never overwrites an existing preset.

<Note>
  So importing the same file twice gives you two copies, not an update. Import is a copy, not a sync.
</Note>

## What does not travel

| | Travels | Why not |
| --- | --- | --- |
| Presets and items | Yes | |
| Preset and item settings | Yes | |
| Store settings | No | They describe the store, not the preset |
| Wording overrides | No | Same |
| Redemption counts | No | A cap's usage belongs to the store that sold it |
| Slug history | No | Old links pointed at the old store |
| The carrier product | No | Set one up on the destination store first |

<Warning>
  Link a carrier product on the destination store **before** you import presets containing custom items. Without one, those items can't be added to a cart, and each such preset's **Health checks** warn that custom items need a carrier product.
</Warning>

## For developers

The routes are `cartpresets/v1/presets/export` and `cartpresets/v1/presets/import`, registered by Pro on the shared `cartpresets_register_rest_routes` action. On free nothing listens, so neither route exists.

See the [REST API](/cartpresets/developers/rest-api).
